# Юрич Мебель — сайт

Лендинг с портфолио, калькулятором и блогом. Обычные HTML/CSS/JS без сборки:
что лежит в папке — то и работает. Никакого npm, node и деплой-скриптов для запуска не нужно.

---

## Что поменять в первую очередь

Все контакты живут в одном файле — **`content/config.js`**. Поменяйте там, и они
подставятся на все страницы сразу:

```js
phone:    '+7 999 123-45-67',   // как показывать
phoneRaw: '+79991234567',       // для ссылки «позвонить»
email:    'info@example.com',
address:  'г. Город, ул. Примерная, 1',
hours:    'Пн–Сб, 9:00–20:00',
whatsapp: '79991234567',        // номер для wa.me
telegram: '',                   // @username — пусто, кнопка скроется
vk:       '',                   // ссылка — пусто, кнопка скроется
formEndpoint: '',               // см. «Куда уходят заявки»
```

Сейчас там **заглушки** — сайт с ними выглядит рабочим, но звонить будут не вам.

Ещё стоит проверить и поправить руками в `index.html`: цифры «8 лет / 400+ / 3 года»,
текст в блоке «О мастерской» и цены в калькуляторе (`<option value="...">` в секции «Заказать расчёт»).

## Куда уходят заявки

**Пока `formEndpoint` пустой** — форма открывает WhatsApp с уже готовым текстом заявки
(имя, телефон, результат калькулятора и отмеченные работы). Ничего настраивать не нужно,
это рабочий вариант на старте.

**Если хотите, чтобы заявки приходили на почту или в CRM** — заведите обработчик формы
(например, бесплатный [Formspree](https://formspree.io) или [Getform](https://getform.io)),
скопируйте оттуда URL и вставьте в `formEndpoint`. Форма начнёт отправлять туда POST-запрос.

## Как изменить коллекции

Коллекции — это модельный ряд: что можно заказать, с материалом фасада и ценой «от».
Живут в **`content/collections.js`**:

```js
{
  "slug": "emal",                       // адрес внутри однофайловой версии
  "name": "Матовая эмаль",
  "tagline": "Короткая строчка под названием",
  "material": "МДФ в эмали, покрытие soft-touch",
  "description": "Абзац для будущей страницы коллекции",
  "priceFrom": 38000,                   // рублей за метр, показывается как «от 38 000 ₽»
  "cover": "emal-1",                    // какое фото на обложке
  "photos": ["emal-1", "emal-2"]        // что листается при нажатии
}
```

Названия в `cover` и `photos` — это файлы из `assets/img/collections/`. Чтобы добавить
туда новое фото, положите исходник в `photos_vardek_clean/`, впишите его в список
`COLLECTION_PHOTOS` в начале `tools/prepare_images.py` и выполните:

```bash
python3 tools/prepare_images.py
```

> Названия, описания и цены в файле сейчас **рабочие заглушки** — замените их на свои
> до публикации.

## Как добавить статью в блог

Откройте **`content/posts.js`** и добавьте блок в начало списка:

```js
{
  "slug": "kak-uhazhivat-za-fasadami",          // адрес: post.html?slug=kak-uhazhivat-za-fasadami
  "title": "Как ухаживать за фасадами",
  "excerpt": "Короткое описание — видно в карточке статьи.",
  "tag": "Советы",                               // Материалы / Планировка / Советы
  "date": "2026-10-01",                          // ГГГГ-ММ-ДД, сортировка идёт по ней
  "read": "5 мин",
  "cover": "assets/img/works/kuhnya-belaya-ostrov.jpg",
  "body": "<p>Текст статьи.</p><h2>Подзаголовок</h2><p>Ещё текст.</p>"
}
```

В `body` можно использовать `<p>`, `<h2>`, `<h3>`, `<ul><li>`, `<blockquote>`, `<strong>`, `<img>`.
Запятые между блоками обязательны, последний блок — без запятой.

Новая статья сама появится на главной, на странице блога и в подвале.

## Как добавить видео

Откройте **`content/videos.js`** и вставьте туда ролики:

```js
window.VIDEOS = [
 {
  "title": "Сборка кухни за один день",
  "embed": "https://www.youtube.com/embed/ВИДЕО_ID",   // именно /embed/, не /watch?v=
  "cover": "assets/img/works/kuhnya-belaya-ostrov.jpg" // превью, можно убрать
 }
];
```

Для RuTube ссылка выглядит как `https://rutube.ru/play/embed/КОД/`, для VK Видео —
её даёт кнопка «Поделиться → Экспортировать».

Пока список пустой, на сайте стоят три подсказки-заглушки — посетитель видит,
что раздел есть, а вы видите, куда вставлять.

## Как посмотреть сайт у себя

Просто откройте `index.html` двойным кликом — всё заработает.

Если хотите «как на настоящем сервере», в папке проекта выполните:

```bash
python3 -m http.server 8000
```

и откройте <http://localhost:8000>.

## Как выложить в интернет

**Vercel** — импортируйте репозиторий на <https://vercel.com/new> и нажмите Deploy.
Настраивать ничего не нужно, `vercel.json` уже всё задаёт. Если Vercel спросит
Framework Preset — `Other`, Build Command оставьте пустым.

Выкладывается **обычный сайт из корня репозитория**, а не версия одним файлом, и это
принципиально. В одном файле весь контент и все фотографии лежат внутри скрипта на
несколько мегабайт: браузер обязан скачать его целиком, и до конца загрузки ниже
первого экрана пусто. На мобильном интернете это секунд десять. Обычная раскладка
отдаёт страницу сразу, а фотографии подгружает по мере прокрутки — на том же канале
текст виден через 0,3 секунды вместо 11.

**GitHub Pages** — **Settings → Pages → Source: Deploy from a branch**, выберите ветку и
папку `/ (root)`. Сайт появится по адресу вида `https://korolxmki.github.io/yurich/`.

Подойдёт и любой обычный хостинг: скопируйте туда всё содержимое папки как есть.

### Весь сайт одним файлом — `dist/odnim-failom.html`

Внутри одного файла лежит всё: лендинг, блог, статьи, стили, шрифты, скрипты
и фотографии. Ни одного внешнего запроса — он открывается двойным кликом
и работает даже без интернета. Блог и статьи доступны по адресам `#/blog`
и `#/post/<slug>`.

Файл **собирается из исходников**, править его руками не нужно. Поменяли контакты
в `content/config.js` или добавили статью в `content/posts.js` — пересоберите:

```bash
pip install pillow
python3 tools/build_single.py
```

Этот файл — чтобы **переслать сайт**: кинуть заказчику в мессенджер, показать
с флешки, открыть без интернета. Для боевого сайта он не годится, почему —
написано выше про Vercel.

## Что где лежит

```
dist/odnim-failom.html ← версия «одним файлом», чтобы переслать (собирается, см. выше)

index.html            главная
collections.html      коллекции целиком
blog.html             список статей и видео
post.html             страница статьи (открывается как post.html?slug=…)

content/config.js     ← контакты и настройки формы
content/collections.js ← коллекции: названия, материалы, цены
content/posts.js      ← статьи блога
content/videos.js     ← видео
content/works.js         портфолио (создаётся скриптом, руками не правим)

assets/css/style.css  все стили
assets/css/fonts.css  шрифты Manrope и Playfair Display — лежат у нас,
                      не зависят от Google Fonts
assets/js/main.js     галерея, фильтры, калькулятор, форма, подборка

assets/img/works/     фото для сайта (ужатые), thumb/ — превью

photos/               исходные фото как прислали, с ватермаркой
photos_clean/         те же фото без ватермарки, полный размер
tools/                служебные скрипты (см. ниже)
```

## Служебные скрипты

Нужны, только если снова понадобится обработать фотографии. Требуют Python:

```bash
pip install pillow opencv-python-headless numpy torch simple-lama-inpainting

python3 tools/remove_watermark.py --dry-run   # показать, где найдена ватермарка
python3 tools/remove_watermark.py             # убрать: photos/ → photos_clean/
python3 tools/prepare_images.py               # сделать веб-версии для сайта
python3 tools/build_single.py                 # собрать версию одним файлом
node tools/check.js                           # проверить сайт браузером (вёрстка, анимации, запас прочности)
```

`tools/remove_watermark.py` ищет значок «B» в кольце звёзд в левом нижнем углу
(он встречается в непрозрачном и полупрозрачном варианте) и закрашивает его
нейросетью LaMa. Какие фото попадают в портфолио, в каком порядке и с какими
подписями — задаётся списком `WORKS` в начале `tools/prepare_images.py`.
