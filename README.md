# Сайт мебельной мастерской · Челябинск

Статический сайт-портфолио: лендинг и каталог работ по разделам. Ни сборки, ни
зависимостей — обычные HTML, CSS и JS, которые можно положить на любой хостинг.

```
index.html               главная: услуги, преимущества, этапы, контакты
works.html               каталог работ: разделы и лайтбокс
assets/css/style.css     все стили, включая анимации появления
assets/js/main.js        шапка, год в подвале, появление блоков
assets/js/works.js       каталог: разделы, лайтбокс
assets/data/gallery.json список фото для каталога (генерируется)
assets/thumbs/           превью 480 px (генерируются)
assets/img/              обложки разделов и фон первого экрана
photos/vk/               оригиналы фотографий, 1080 px
scripts/build_gallery.py пересборка превью и gallery.json
scripts/build_dist.py    сборка dist/ для хостинга
```

## Как устроен каталог

Вкладки — разделы; вкладки «Все работы» нет. В каждом разделе показываются
последние работы, не больше `LIMIT` штук: константа в начале `assets/js/works.js`
(сейчас 10). Увеличили её — не забудьте пересобрать `dist/`, чтобы в сборку
попали новые фотографии.

Блоки появляются при прокрутке через `IntersectionObserver` (`assets/js/main.js`).
То, что уже в кадре или выше него, показывается сразу, остальное всплывает со
сдвигом по соседям. Вся анимация живёт под классом `.js`, который ставит сам
скрипт: без JS страница просто видна целиком, а при системной настройке
«уменьшить движение» анимации выключаются. Плавная прокрутка — `scroll-behavior`
со `scroll-padding-top` под липкую шапку.

## Сборка для хостинга

```bash
python3 scripts/build_dist.py            # dist/ — только нужные фото, в WebP
python3 scripts/build_dist.py --limit 20 # если в разделах стало больше работ
```

Скрипт кладёт в `dist/` те фотографии, которые действительно показываются
(последние `--limit` в каждом разделе), переводит их в WebP, переписывает пути
в HTML и `gallery.json`. Выходит около 5 МБ — такую папку или архив из неё
можно перетащить в Vercel Drop: у бесплатного тарифа лимит загрузки 100 МБ,
а исходные JPEG весят 295 МБ. `dist/` в git не хранится.

## Посмотреть локально

Каталог читает `gallery.json` через `fetch`, поэтому просто открыть `index.html` двойным
кликом не получится — нужен любой локальный сервер:

```bash
python3 -m http.server 8000
# затем http://127.0.0.1:8000/
```

## Опубликовать

Подойдёт любой статический хостинг. На GitHub Pages: **Settings → Pages → Deploy from a branch**,
ветка текущая, папка `/ (root)`. Файл `.nojekyll` уже лежит в корне.

## Добавить фотографии

1. Положить снимки в `photos/vk/<раздел>/` с именем вида `2026-09-27_12345.jpg`
   (разделы: `kuhni`, `shkafy-kupe`, `gorki`, `stoly`, `prihozhie`, `detskie`, `lenta`).
2. Выполнить `python3 scripts/build_gallery.py` — пересоберёт превью и `gallery.json`.
   Уже существующие превью не трогаются, так что прогон быстрый.
3. Поправить счётчики фото на главной (`index.html`, блок «Что мы делаем») и в заголовках.

Новый раздел добавляется в объект `CATS` в `assets/js/works.js` — название оттуда попадёт
в фильтры и лайтбокс.

мессенджеры работают без бэкенда.

## Фотографии

Все фотографии лежат в `photos/`.
Поддерживаемые форматы: `.jpg`, `.jpeg`, `.png`, `.webp`, `.heic`.

при необходимости нужно перезапрашивать заново.
